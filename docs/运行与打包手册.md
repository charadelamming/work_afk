# 运行与打包手册（精简版）

> 目标：拿到仓库后，**在 10 分钟内把界面跑起来**；需要桌面版时，再把安装包打出来。
> 所有命令都在仓库根目录（`work_afk/`）执行。

---

## 1. 前置条件

| 用途 | 需要 |
| --- | --- |
| 只看界面 / 跑测试 | Node 18+、pnpm |
| 桌面版（`tauri dev` / `tauri build`） | 上面 + Rust stable-msvc + VS 2022 生成工具（C++ 桌面开发 + Windows 11 SDK） |
| 运行桌面版 | Windows 10/11 x64，WebView2 运行时（系统自带；本项目锁定 Tauri 2.10.3，见第 5 节） |

检查环境（只读，不装任何东西）：

```powershell
pnpm check:env
# 或
powershell -ExecutionPolicy Bypass -File scripts\check-env.ps1
```

输出会逐项列出 Node / pnpm / cargo / MSVC / Windows SDK / WebView2 / 依赖 / 图标的状态，末尾给结论。

## 2. 三种运行方式，按需选

| 我想…… | 用这个 | 需要 Rust |
| --- | --- | --- |
| 快速看界面、调样式 | `pnpm dev` + 浏览器 | 否 |
| 开发桌面版（托盘、置顶、自启） | `pnpm tauri dev` | 是 |
| 给别人用 | 打安装包（第 5 节） | 是 |

### 2.1 只看界面（最快）

```bash
pnpm install
pnpm dev
```

打开：

- 悬浮窗 <http://127.0.0.1:1420/index.html>
- 设置页 <http://127.0.0.1:1420/settings.html>

浏览器里会自动铺一层桌面背景方便预览，配置走 `localStorage`，行为与真实窗口一致（托盘、自启这类系统能力除外）。

> 端口固定 1420，`strictPort` 不会自动换端口；被占用时先关掉占用的进程。

### 2.2 桌面开发模式

```bash
pnpm tauri dev
```

Vite 先起在 1420，Tauri 再加载它。改前端代码热更新，改 `src-tauri` 下的 Rust 代码会触发重新编译（首次较慢）。

## 3. 从零搭环境

### 3.1 一键脚本（推荐）

```powershell
# 装环境 + pnpm install + 自检 + 直接打包
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1

# 只装环境，不打包
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1 -SkipBuild

# 国内网络：crates 走 rsproxy、npm 走 npmmirror
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1 -CratesMirror rsproxy -NpmRegistry https://registry.npmmirror.com
```

脚本特性：

- 每一步先检测「已装则跳过」，可以反复执行；
- 会请求一次提权来装 VS 生成工具；
- VS 安装是异步的，脚本会轮询 `link.exe` 和 `kernel32.lib` 直到就绪（可能十几分钟）；
- 遇到「MSVC 装了但 SDK 没装」会单独补装 SDK。

### 3.2 手动装（四件套）

1. **Node 18+**：<https://nodejs.org/>（或 `winget install OpenJS.NodeJS.LTS`）
2. **pnpm**：`npm i -g pnpm`
3. **Rust**：`winget install Rustlang.Rustup`，然后确认 `rustup default stable-msvc`
4. **VS 2022 生成工具**：`winget install Microsoft.VisualStudio.2022.BuildTools`，在安装器里勾「使用 C++ 的桌面开发」+ Windows 11 SDK

装完先跑 `pnpm check:env` 确认全绿，再 `pnpm install`。

## 4. 日常命令

| 命令 | 作用 |
| --- | --- |
| `pnpm dev` | 起 Vite（1420），浏览器预览两个页面 |
| `pnpm tauri dev` | 起桌面版开发模式 |
| `pnpm build` | 类型检查 + 构建前端到 `dist/` |
| `pnpm preview` | 预览构建产物（4173），截图和布局核查要先起它 |
| `pnpm check` | 全量门禁：`vue-tsc` + 94 断言 + 5 变异 + 98 Vitest |
| `pnpm test` | 只跑 Vitest |
| `pnpm check:calc` | 只跑计薪引擎自检 |
| `pnpm check:mutate` | 只跑变异测试 |
| `pnpm shot` | 用系统 Edge 重拍 10 张截图（需先 `pnpm preview`） |
| `pnpm check:layout` | 布局断言（需先 `pnpm preview`） |
| `pnpm icons` | 重新生成图标（需 Python + Pillow） |

收工前至少跑一次 `pnpm check`。改动计薪规则时，必须同步更新 `scripts/lib/checks.cjs` 与 `tests/unit/pay.spec.ts` 的断言。

## 5. 打包

```powershell
pnpm tauri build
```

流程：`vue-tsc --noEmit` → `vite build` → `cargo build --release` → 打 NSIS 包。本机 release 编译约 1–3 分钟。

产物：

| 文件 | 说明 |
| --- | --- |
| `src-tauri\target\release\reborn-work.exe` | 免安装单体 exe，约 3.29 MB，双击即跑 |
| `src-tauri\target\release\bundle\nsis\重生之我挂机上班_0.1.0_x64-setup.exe` | NSIS 安装包，约 1.22 MB |

只想要 exe、不打包：

```powershell
pnpm tauri build --debug --no-bundle   # 调试版，快
```

安装包配置（`src-tauri/tauri.conf.json`）：

- `installMode: currentUser`：装到 `%LOCALAPPDATA%\重生之我挂机上班`，写 HKCU，**不需要管理员**；
- `languages: ["SimpChinese"]`；
- 未做代码签名，首次运行会被 SmartScreen 拦一下（「更多信息 → 仍要运行」）。

### 5.1 依赖版本锁定（不要单独升级 Tauri）

`src-tauri/Cargo.toml` 固定了 `tauri = "=2.10.3"`、`tauri-runtime-wry = "=2.10.1"`（实际 wry 0.54.4），`package.json` 固定 `@tauri-apps/api = "2.10.1"`。原因是 Tauri 2.12.5 / wry 0.57.1 在部分 Windows + WebView2 157 环境会在建窗阶段失败：

- 启动进程直接崩溃：Windows 事件日志 `0xc0000409`（BEX64）；
- 或 Tauri 报 `0x8000FFFF`「灾难性故障」/ `0x800700AA`「请求的资源在使用中」；
- 或进程一直在、托盘也有，但主窗口和 `msedgewebview2.exe` 子进程都不出现。

升级 Tauri / `@tauri-apps/api` 前，必须在一台干净的 Windows 机器上做「启动 → 出现 380×172 窗口」回归；只跑 `pnpm build` 或单测发现不了这类问题。

## 6. 安装 / 卸载验收

> 不要把安装包直接从深层工作区路径（`D:\...\target\release\bundle\nsis\`）启动，某些环境会挂起。**先复制到普通目录再运行。**

```powershell
# 1. 复制到临时目录
Copy-Item '.\src-tauri\target\release\bundle\nsis\*.exe' C:\Temp\ -Force

# 2. 静默安装
Start-Process C:\Temp\重生之我挂机上班_0.1.0_x64-setup.exe -ArgumentList '/S' -Wait

# 3. 验收四件事
Test-Path "$env:LOCALAPPDATA\重生之我挂机上班\reborn-work.exe"          # 程序文件
Test-Path "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\重生之我挂机上班.lnk"  # 快捷方式
Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*' |
  Where-Object DisplayName -like '*挂机*'                                # 卸载项
Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run' -ErrorAction SilentlyContinue  # 自启项（若开启）

# 4. 静默卸载
Start-Process "$env:LOCALAPPDATA\重生之我挂机上班\uninstall.exe" -ArgumentList '/S' -Wait
```

卸载后确认目录、开始菜单快捷方式、HKCU 卸载项都已清除。

## 7. 故障速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `pnpm` 报「禁止运行脚本」 | PowerShell 执行策略 | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned -Force` |
| `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION` | pnpm 12 拒绝 24 小时内新包 | 按报错包名加进 `pnpm-workspace.yaml` 的 `minimumReleaseAgeExclude`，或设 `minimumReleaseAge: 0` |
| `ERR_PNPM_IGNORED_BUILDS` | 构建脚本未审核 | 按提示把 `allowBuilds` 里的占位值改成 `true`（本项目已放行 esbuild） |
| 1420 端口被占用 | 上次 dev 没退干净 | 结束占用进程，或重启终端 |
| `cargo` 拉 crates 超时 | 网络 | `-CratesMirror rsproxy` 重跑 setup，或配 `~/.cargo/config.toml` |
| 链接阶段缺 `kernel32.lib` | MSVC 已装但 Windows SDK 缺失 | 补装 Windows 11 SDK，`check-env.ps1` 会指出来 |
| `tauri dev` 窗口白屏后退出 | WebView2 建窗失败 | 见下条 |
| 启动即崩，事件日志 `0xc0000409` / BEX64 | Tauri 2.12.5 + wry 0.57.1 与 WebView2 157 不兼容 | 确认 `Cargo.toml` 锁在 2.10.3、`package.json` API 锁在 2.10.1；`cargo update -p tauri --precise 2.10.3` 后重打 |
| 进程在、有托盘，但没有主窗口 | WebView2 controller 创建失败，常见 `0x8000FFFF` / `0x800700AA` | 先重启清掉僵尸 `msedgewebview2.exe`；删除 `%LOCALAPPDATA%\com.rebornwork.app\EBWebView` 后重试；仍失败则修复/重装 WebView2 运行时，换普通桌面会话或干净机器验证 |
| `msedgewebview2.exe` 崩溃（`0x80000003`） | WebView2 运行时或宿主环境异常 | 修复/重装 WebView2；删除 `%LOCALAPPDATA%\com.rebornwork.app\EBWebView` 后重试；必要时重启。**不是** `%APPDATA%` 下的目录 |
| 双击安装包没反应 | 安全软件拦截深层路径 | 复制到下载目录 / `C:\Temp` 再运行 |
| 配置写坏后起不来 | 手改 `config.json` | 删除 `%APPDATA%\com.rebornwork.app\config.json` 即回默认值；代码本身也会做字段清洗 |
| 系统提示有待重启文件 | VS 安装中断 | 重启后再跑 setup |

> **「有进程、无窗口」的推荐排查顺序**：① 退出所有 `reborn-work.exe` 和 `msedgewebview2.exe`，重启；② 删除 `%LOCALAPPDATA%\com.rebornwork.app\EBWebView` 再启动；③ 修复/重装 WebView2 Evergreen 运行时；④ 换一个普通桌面会话或干净 Windows 机器验证。若只有 DSH/自动化会话里无窗口、用户手动双击正常，优先怀疑会话桌面隔离，而不是程序本身。
