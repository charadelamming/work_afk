# 更新记录

> 记录对用户可见的功能变化、重要修复和仍然遗留的问题。日期按本地时间（Asia/Shanghai）。

## 2026-11-09

本次共处理 5 个问题，另根据反馈调整了拖动时的鼠标样式。

### 1. 窗口无法拖动

**现象**：按住标题、品牌名、金额或空白处拖动，窗口不动；只有极少数位置能拖。

**原因**：Tauri 的拖动脚本只认「鼠标事件目标元素自身」上的 `data-tauri-drag-region`。原实现只给 `.brand`、中间的 `<span>`、`.date-chip` 加了属性，点 SVG 图标、品牌行内边距或金额时，事件目标不是这些元素，拖动条件不成立。

**修改**：

- 把 `data-tauri-drag-region` 放到整张 `.card` 上；
- `.bar`、`.money`、`.status`、`.track`、`.scale`、`.stats` 等非交互区域设 `pointer-events: none`，让鼠标命中 `.card`；
- `.bar__actions` 恢复 `pointer-events: auto`，三个按钮仍可点击；
- 移除 `.brand` / 内部 `<span>` / `.date-chip` 上重复的属性，避免以后升级 Tauri 2.12 时触发它的 early-return 逻辑。

**验证**：卡片空白、金额、状态行、进度条均可发起拖动；按钮点击不触发拖动。

### 2. 窗口边缘的正方形阴影

**现象**：圆角卡片外围有一圈方形、发灰的阴影，透明窗口的四个角尤其明显。

**原因**：`.card` 同时用了 `box-shadow: var(--shadow-card), inset ...`，其中外层阴影是 34px 大模糊；`.widget-body` 只有 4px 内边距且 `overflow: hidden`，模糊被矩形窗口裁掉，只剩一圈方形边界。

**修改**：`src/styles/widget.css` 中移除 `.card` 的外层 `var(--shadow-card)`，只保留 `inset 0 1px 0 rgba(255,255,255,.9)` 高光和原来的 1px 边框。窗口本身仍是透明、无系统阴影。

**验证**：截图和真机边缘不再出现方形光晕，圆角与边框保持清晰。

### 3. 右上角按钮 hover 背景偏左

**现象**：鼠标移到图钉 / 设置 / 隐藏按钮上，灰色圆角背景相对图标整体偏左。

**原因**：`.ico` 是原生 `<button>`，只设了宽高 21px、`display: grid`、`border: 0`，没有清掉浏览器默认的 `padding` 和行高；图标被默认内边距推向一侧，背景却按按钮盒居中。

**修改**：`.ico` 改为 `display: flex` + `align-items/justify-content: center`，补 `padding: 0`、`line-height: 0`、`appearance: none`、`flex: none`，并让 `.ico svg { display: block; }`。

**验证**：三个按钮的图标中心与 21×21 背景中心偏差均为 0。

### 4. 底部统计栏可开关（默认隐藏）

**现象**：底部「时薪 / 每秒 / 本月已赚」一直显示，占掉窗口约 40px 高度，无法隐藏。

**修改**：

- `src/core/types.ts` 新增 `showStats: boolean`，`DEFAULT_SETTINGS.showStats = false`；
- `src/platform/config.ts` 的 `normalizeSettings()` 增加 `showStats` 清洗，老配置缺字段时自动落到 `false`；
- `src/widget/WidgetApp.vue` 给 footer 加 `v-if="settings.showStats"`；
- 新增 watcher：`showStats` 变化时调用 `resizeCurrentWindow(380, showStats ? 212 : 172)`；
- `src/platform/window.ts` 新增 `resizeCurrentWindow()`，`src-tauri/capabilities/default.json` 增加 `core:window:allow-set-size`；
- `src/settings/SettingsApp.vue` 在「显示与行为」里新增「底部统计栏」开关，说明文字为「显示时薪、每秒和本月已赚；关闭后小组件更紧凑」。

**行为**：

- 默认窗口 380×172，只显示金额、状态、进度条；
- 打开开关后窗口变为 380×212，底部三列统计出现；
- 设置通过现有的 450ms 自动保存 + `BroadcastChannel`/Tauri event 同步，无需重启。

**验证**：组件测试覆盖默认隐藏、开启后出现；截图确认 172/212 两种高度都不裁切。

### 5. 免安装单体 exe 无法启动（已定位、部分缓解、未彻底解决）

**现象**：`pnpm tauri build` 产出的 `src-tauri\target\release\reborn-work.exe` 双击后进程很快消失；Windows 事件日志为 `reborn-work.exe`、异常 `0xc0000409`（BEX64）。旧调试版还能看到 Tauri panic：

```text
Failed to setup app: runtime error: failed to create webview:
WebView2 error: WindowsError(Error { code: HRESULT(0x8000FFFF), message: "灾难性故障" })
```

也出现过 `0x800700AA`「请求的资源在使用中。」。

**定位过程（摘要）**：

- 用最小 Tauri 复现工程、不同 identifier、干净 profile、不同窗口样式、`--no-sandbox`、`transparent:false`、`dataDirectory` 均能复现；
- Tauri 2.12.5 / wry 0.57.1 下崩溃；在这台诊断机上降到 Tauri 2.10.3 / wry 0.54.4 后不再 BEX64；
- 但在这台诊断机上，WebView2 环境创建成功，`CreateCoreWebView2ControllerWithOptions` 仍然失败（`0x800700AA` 或 `0x8000FFFF`），主窗口和 `msedgewebview2.exe` 子进程都不出现；
- 同一台机器用原生 C++ WebView2 探针（系统 157 运行时、普通窗口、子窗口、隐藏窗口、Tauri 风格参数、固定 156 运行时）均能创建 controller，说明运行时本身正常，问题集中在 Tauri/wry 集成与该机器环境的组合。

**已做的缓解**：

- `src-tauri/Cargo.toml` 锁定 `tauri = "=2.10.3"`、`tauri-runtime-wry = "=2.10.1"`（wry 0.54.4）；
- `package.json` 锁定 `@tauri-apps/api = "2.10.1"`；
- 在这台诊断机上重新打包后不再出现 `0xc0000409` 硬崩溃。

**当前状态**：**不能称为已修复**。在用户真实桌面上程序可以正常显示和拖动；在诊断机上仍会「进程在、无窗口」。如果遇到同样现象，按 [运行与打包手册](运行与打包手册.md) 第 7 节处理：重启清理残留 WebView2 进程 → 删除 `%LOCALAPPDATA%\com.rebornwork.app\EBWebView` → 修复/重装 WebView2 运行时 → 换干净机器验证。

### 6. 拖动时鼠标样式保持默认

**现象**：为了提示可拖动，之前给卡片加了 `cursor: grab`，按下时变 `grabbing`；用户希望拖动时也保持系统默认箭头。

**修改**：删除 `.card` 的 `grab` / `grabbing` 规则；`.widget-body` 保持 `cursor: default`，只有 `.ico` 按钮保留 `cursor: pointer`。

**验证**：拖动卡片时鼠标不再变成手形或抓取形。

## 兼容性说明

- 旧版 `config.json` 没有 `showStats` 字段，读取时会自动补 `false`，不需要手动迁移。
- 首次升级后窗口会从 212 高收到 172；如果希望保留统计栏，在设置里重新打开即可。
- 如果从旧版 Tauri 2.12.x 的构建产物升级，建议先退出托盘、删除旧的 `EBWebView` 缓存，再用新 exe 启动。
